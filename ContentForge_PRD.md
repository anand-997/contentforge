## 1. Problem Statement

QA Walah is a solo content creator building a personal brand in software testing, SDET engineering, and AI-powered QA across five platforms — LinkedIn, Medium, Instagram, YouTube, and dev.to. Publishing high-quality, platform-native content daily across all five channels requires 3–5 hours of manual work per day, making it unsustainable alongside active engineering work.

ContentForge is a locally hosted, fully automated content pipeline that runs every morning, picks a fresh topic from configured content pillars, generates platform-specific content in the creator's authentic voice, produces branded images, and stores everything in a structured Excel file — ready to copy, paste, and publish within 10 minutes each morning.

The system must produce content that reads as written by a senior QA engineer with real opinions — not as generated by an AI tool.

---

## 2. Goals

- **G1 — Zero daily effort for content generation.** One pipeline run produces all five platform outputs, fully formatted and brand-consistent, without human input.
- **G2 — Authentic, human-sounding voice.** All content matches the QA Walah voice fingerprint. No post should be identifiable as AI-generated by platform moderation systems or readers.
- **G3 — Platform-native formatting.** Each platform output follows that platform's actual content strategy — not a reformatted version of the same text.
- **G4 — Full local operation.** No cloud storage, no SaaS, no database. Only outbound calls are to Deepseek API and Gemini API.
- **G5 — Real-time dashboard visibility.** The creator watches each agent complete its step live, without refreshing.
- **G6 — Recoverable and resilient pipeline.** Any agent failure leaves the system in a known state. Re-triggering from the UI resumes from the failure point without data loss.
- **G7 — 10-minute morning publish workflow.** The dashboard gives the creator a per-platform publish checklist so the full publishing task takes under 10 minutes.

---

## 3. Non-Goals

- **No auto-publishing (v1).** ContentForge generates content only. The creator publishes manually. Auto-posting is planned for Agent 5 in v2.
- **No multi-user support.** Single-machine, single-user local tool. No auth, no sessions.
- **No Google Sheets sync.** All data lives in local `content_calendar.xlsx` only.
- **No video or audio generation.** YouTube output is a text script only.
- **No bulk or future-date scheduling.** One topic per day, generated the same morning.
- **No mobile responsiveness.** Desktop-only local tool in v1.
- **No content editing inside the dashboard.** Read-only content view. Editing happens in the platform directly.

## 5. User Stories

### Content Generation

- As QA Walah, I want the pipeline to run automatically at 9:00 AM IST every day so that content is ready before I start my morning review.
- As QA Walah, I want to manually trigger the pipeline from the dashboard so that I can regenerate content or run it outside the scheduled time.
- As QA Walah, I want the pipeline to rotate across my four content pillars so that my content covers different topics across the week without manual planning.
- As QA Walah, I want the pipeline to rotate across different post structures (story, contrast, hot-take, numbered-insight, question-led) so that no two consecutive posts feel structurally identical.
- As QA Walah, I want the topic generator to avoid repeating topics already in the sheet so that my content stays fresh indefinitely.
- As QA Walah, I want each platform output formatted correctly for that platform so that I can copy-paste without any reformatting.

### Dashboard & Workflow

- As QA Walah, I want to see today's topic, all five content pieces, and all images in one tab so that I can review everything without opening the Excel file.
- As QA Walah, I want a copy-to-clipboard button on every content section so that I can paste directly into each platform.
- As QA Walah, I want a Daily Publish Checklist tab that tells me exactly what to do on each platform (in order) so that my morning publishing takes under 10 minutes.
- As QA Walah, I want the dashboard to show the best posting time for each platform today so that I publish at the right time without remembering it myself.
- As QA Walah, I want a content streak counter showing how many consecutive days the pipeline ran successfully so that I stay motivated to publish daily.
- As QA Walah, I want to see live pipeline progress as each agent completes its step so that I know what is happening without checking logs.
- As QA Walah, I want API key health indicators on the dashboard so that I know before running the pipeline if a key has expired.

### Reliability

- As QA Walah, I want failed pipeline runs to be re-triggerable from the UI so that a Deepseek timeout does not mean I lose that day's content.
- As QA Walah, I want every pipeline event logged to a file so that I can debug failures without reading source code.
- As QA Walah, I want the Excel file to be uncorruptible even if the pipeline crashes mid-write so that I never lose historical content.

### Key Architectural Decisions

**Pipeline lock (`pipelineLock.ts`):** In-memory boolean mutex. If the pipeline is already running when `POST /api/run` arrives, the API returns `409 Conflict`. Prevents double runs from cron + manual trigger overlap.

**ExcelManager mutex:** All reads and writes are serialized via a promise chain queue (`writeQueue = writeQueue.then(() => doWrite())`). Guarantees sequential, non-concurrent writes. Pattern: `readWorkbook → mutate in memory → writeWorkbook`.

**Scheduler isolation:** Initialized once via Next.js `instrumentation.ts` (App Router server singleton hook). Never inside React components or route handlers.

**SSE for live updates:** `GET /api/stream` pushes real-time status events to the dashboard. Polling `GET /api/status` every 3 seconds is the automatic fallback.

**ConfigManager (`configManager.ts`):** Reads and writes `contentforge.config.json`. All runtime-configurable values (cron schedule, Deepseek model, Gemini model, content pillars, post structure rotation) live here — not hardcoded.

**VoiceEngine (`voiceEngine.ts`):** Builds the system prompt for Agent 2 dynamically from the brand voice rules, few-shot examples, current pillar tone hint, and current post structure. This is the single most critical module for content quality.

### Deepseek API Integration Note

Deepseek exposes an OpenAI-compatible REST API. Use the `openai` npm package pointed at Deepseek's base URL — no separate Deepseek SDK required:

```typescript
import OpenAI from "openai"

const deepseek = new OpenAI({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com",
})
```

The model name is configurable in `contentforge.config.json`. Common values:

| Model | Best For | Speed |
|---|---|---|
| `deepseek-chat` | Content writing, topic generation | Fast |
| `deepseek-reasoner` | Structured reasoning, long-form articles | Slower |

Default: `deepseek-chat`. The creator can change this from the dashboard config UI without restarting the app.

### Gemini Image Model Note

Use `@google/genai` SDK with model `gemini-2.0-flash-preview-image-generation`. This model returns base64-encoded image data that must be decoded and saved as PNG files. Model name is configurable in `contentforge.config.json`. Validate the model name on startup and log a warning if it has changed.

```

```

### Row Collision Rules

| Existing Status | Pipeline Triggered Again | Action |
|---|---|---|
| `Done` | Manual or cron | Skip entirely. Log: "Already completed for today." |

## 11. Brand Voice System

This is the most critical section in the entire PRD. Agent 2's output quality depends entirely on how well the voice system prompt is constructed. This section defines the exact system prompt rules, few-shot examples, and anti-patterns that `voiceEngine.ts` injects into every Agent 2 call.

### 11.1 Voice Fingerprint (QA Walah)

Extracted from real post analysis:

**Structural patterns:**
- Opens with a real scenario or moment — never a definition, never a topic statement
- Builds tension through a story or contrast before delivering the insight
- Delivers insights in short, punchy lines after narrative buildup
- Ends with a PS question that is specific to the post's scenario — not generic
- Never concludes with "in summary", "takeaway", or "in conclusion"

**Sentence rhythm:**
- Mixes long narrative paragraphs with sudden one-liners
- Uses direct address: "you", "your team", "your agent"
- Asks questions mid-post, not just at the end
- Uses conversational pivots: "Here is the thing.", "That was the moment.", "That is the shift."

**Opinion signature:**
- Takes a clear side — never "it depends"
- Respects the reader's intelligence — no over-explaining
- Challenges without insulting
- Uses specific real numbers over vague claims (`114K tokens`, `~27K`, `4x`)

### 11.2 Voice Rules for Agent 2 System Prompt

These rules are injected verbatim into every Agent 2 prompt via `voiceEngine.ts`:

```
VOICE RULES — follow these exactly:

1. NEVER open with a topic statement or definition. Open with a real moment, a scenario, or a number.
2. NEVER use arrow lists (→) more than once per post. Vary the format.
3. NEVER use "The gap is..." as a closing device.
4. NEVER start three consecutive sentences the same way.
5. NEVER use: "game-changer", "dive deep", "in today's world", "it's important to note",
   "let that sink in", "unpopular opinion:", "hot take:", "in conclusion", "to summarize",
   "as an SDET", "in the age of AI", "revolutionize", "unlock", "leverage".
6. NEVER use em-dashes (—) decoratively. Use a period or rewrite the sentence.
7. NEVER use special characters (✅ ❌ 🚀 →) in article body text.
8. ONE opinion per post. State it once. Do not restate it three different ways.
9. The PS question must be specific to this post's scenario. Not generic engagement bait.
10. Use specific numbers. "4x cost" beats "much higher cost". "114K tokens" beats "many tokens".
11. Short paragraphs. 1–3 sentences max per paragraph for LinkedIn and Instagram.
12. Write as one engineer talking to one other engineer. Not as a content creator.
13. VARY THE STRUCTURE. Check the current assigned structure type and follow it strictly.
14. Do NOT sound like the post was written by an AI. Read it back. If it sounds like a listicle
    or a newsletter, rewrite it.
```

### 11.3 Post Structure Definitions

Agent 2 receives the current structure type from the config rotation. It must follow the assigned structure — not default to arrow lists every time.

**Structure: `story`**
- Opens with a specific real-world scenario (interview, production incident, team meeting)
- Builds character and tension through the narrative
- The insight emerges from the story — it is not stated upfront
- Ends with a reflection or question about the reader's own experience
- Format: flowing prose, minimal lists

**Structure: `contrast`**
- Opens with what most people do / think / say
- Contrasts immediately with what experienced engineers do
- Uses parallel structure but does NOT use arrow lists — use sentence pairs instead
- Ends with the principle that explains the contrast
- Format: alternating short paragraphs

**Structure: `hot-take`**
- Opens with one bold, specific, potentially controversial statement
- Defends it with evidence, numbers, or a real example
- Acknowledges the counterargument briefly — then dismisses it with reasoning
- No hedging. No "in my opinion". Just the take and the defense.
- Format: short paragraphs, punchy

**Structure: `numbered-insight`**
- Opens with a specific problem or question
- Delivers N insights (3–5) — each insight is a short paragraph, not a bullet point
- Numbers are used as anchors, not decoration: "The first thing..." not "1."
- Each insight is specific, not generic
- Format: narrative with numbered anchors

**Structure: `question-led`**
- Opens with the uncomfortable question the reader is already thinking
- Answers it directly — no buildup, no preamble
- Then explains why that answer is correct, with a real example
- Ends with a second question that takes the reader one level deeper
- Format: tight, Q&A-style prose

### 11.4 Few-Shot Examples for Agent 2

Three real QA Walah posts are stored as few-shot examples in `voiceEngine.ts`. These are passed to Agent 2 as `role: "user"` + `role: "assistant"` pairs before the generation prompt. They teach the model the exact voice without explaining it.

**Example 1 — Structure: `story` — Pillar: `career`**
(The interview post — automation tester who could not debug without AI)

**Example 2 — Structure: `numbered-insight` — Pillar: `ai-tools`**
(The 5 AI terms post — tokens, context window, hallucination, RAG, temperature for QA)

**Example 3 — Structure: `contrast` — Pillar: `automation`**
(The feature flag test design post — weak pattern vs senior SDET pattern)

Note: These are stored as constants in `voiceEngine.ts`. When Agent 2 is called, two of the three most relevant examples (by pillar match) are injected as few-shot context.

### 11.5 Anti-AI-Detection Rules

These structural rules reduce the likelihood of content being flagged by LinkedIn, Instagram, or Medium moderation as AI-generated:

- Vary sentence length within every paragraph — mix short (4–6 words) and long (15–20 words) sentences
- Include at least one piece of specific, verifiable information per post (a real tool name, a real number, a real scenario type)
- Never use a list with more than 5 items
- Never use identical sentence openers within 3 lines of each other
- Include at least one imperfect or colloquial phrase per post — something a human would say but a model would smooth out
- The PS question must never end with a question mark followed by a hashtag in the same paragraph

## 12. Content Pillar System

### Pillar Rotation Logic

Agent 1 reads `lastUsedPillar` and `lastUsedStructure` from the config file before selecting today's pillar and structure.

**Pillar selection (weighted rotation):**
- Build a list of pillars ordered by: pillars not used recently first, then by weight descending
- Select the top pillar from this ordered list
- Write the selected pillar ID to `lastUsedPillar` in config after selection

**Structure selection (sequential rotation):**
- Read `lastUsedStructure` from config
- Pick the next structure in the `postStructures` array (wrap around after the last)
- Write the selected structure to `lastUsedStructure` in config after selection

**Result:** Over any 5-day period, all five structures are used exactly once. Over any 7-day period, all four pillars are covered in proportion to their weights. No two consecutive days have the same structure. Pillar repetition within 2 days is avoided.

## 13. Platform Content Strategy

Each platform has a different content DNA. Agent 2 receives platform-specific instructions for every output. This section defines those instructions.

### 13.1 LinkedIn

**What works in 2026:**
- First line must stop the scroll — it appears before "See more" and decides if anyone reads further
- No hashtags in post body — they reduce reach. Hashtags go in the FIRST COMMENT (stored separately in `LinkedInHashtags` column)
- Maximum 3 sentences per paragraph, heavy white space
- Personal scenario + professional insight outperforms pure advice
- Best posting time: 8:00 AM IST (configured in `platformPostingTimes`)

**Rotating post formats (assigned by structure rotation):**

| Structure | LinkedIn Execution |
|---|---|
| `story` | Narrative arc — opens mid-scene, insight emerges from the story |
| `contrast` | "Most QA engineers do X. Senior SDETs do Y." — sentence pairs, no arrows |
| `hot-take` | One bold opening line. Defend it. No hedging. |
| `numbered-insight` | 3–5 insights as short paragraphs with numbered anchors |
| `question-led` | Open with the uncomfortable question. Answer it. Go deeper. |

**Output requirements:**
- Post body: 150–200 words
- Hashtags: 5 relevant hashtags stored separately (for first comment)
- NO special characters in body
- PS question at the end: specific to this post's scenario

### 13.2 Medium

**What works in 2026:**
- SEO drives most Medium distribution — title must contain the exact search phrase
- Subtitle (kicker) appears in preview — must hook immediately
- 7–9 minute read time is the sweet spot
- First paragraph appears in preview — must be strong
- Cross-posting to dev.to requires canonical URL pointing to Medium

**Output requirements:**
- Creative title (`MediumTitle`): engaging, click-worthy
- SEO slug (`MediumSlug`): hyphenated, keyword-rich, lowercase
- Subtitle/kicker (`MediumSubtitle`): one sentence, makes you click
- Meta description (`MediumMetaDesc`): 155 characters, includes primary keyword
- Article body (`Medium`): ~3000 words, Markdown
- Structure: Intro → Problem → Core Concept → Practical Example (with real code if relevant) → Common Mistakes → Summary
- No filler headings ("Introduction", "Conclusion") — use descriptive H2s

### 13.3 Instagram

**What works in 2026:**
- Clean images with NO text overlay — caption carries the content (as specified by creator)
- Caption line 1 is the hook — Instagram hides content after 3 lines ("...more")
- Line breaks between every 1–2 sentences — Instagram readers scan vertically
- 3–5 hashtags at the end of caption (still work for discovery on Instagram unlike LinkedIn)
- Best posting time: 9:00 AM IST

**Caption structure:**
```
[Line 1: Hook — one punchy sentence that makes them tap "more"]
[blank line]
[Lines 2–8: Content — broken into single lines, max 2 sentences each]
[blank line]
[CTA line: "Save this for your next sprint planning." or similar]
[blank line]
#hashtag1 #hashtag2 #hashtag3 #hashtag4 #hashtag5
```

**Output requirements:**
- Full caption following the structure above (~150–250 words)
- 5 relevant hashtags embedded in caption
- Images: clean branded cards (see Section 18) — no text on image

### 13.4 YouTube

**What works in 2026:**
- Title and thumbnail determine 95% of views — script is secondary
- Hook must land in first 30 seconds — retention drop at 30s kills algorithm ranking
- Chapter titles in description improve watch time
- YouTube description is what YouTube search indexes

**Output requirements:**
- Script (`YouTube`): Full spoken-word script with timestamp markers
  - `[00:00–00:30]` Hook — why this matters right now
  - `[00:30–01:00]` Intro — who this is for
  - `[01:00–08:00]` Main content — with `[B-ROLL SUGGESTION]` markers
  - `[08:00–09:00]` Recap — 3 key points in 60 seconds
  - `[09:00–09:30]` Outro — subscribe CTA + next video mention
- Three title options (`YouTubeTitle1`, `YouTubeTitle2`, `YouTubeTitle3`):
  - Option 1: `"[Number] things every [role] needs to know about [topic]"`
  - Option 2: `"Why your [X] keeps [failing/breaking/costing more] (and how to fix it)"`
  - Option 3: `"I [did X] for [Y days/projects]. Here's what actually happened."`
- YouTube description (`YouTubeDescription`):
  ```
  [2–3 sentence hook paragraph]

  CHAPTERS:
  00:00 — [chapter title]
  01:00 — [chapter title]
  ...

  LINKS:
  GitHub / tools mentioned / related videos (placeholder — creator fills in)

  [5–8 keywords as natural sentences, not a keyword dump]

  Subscribe for weekly QA, SDET, and AI testing content.
  @qawalah
  ```

### 13.5 Dev.to

**What works in 2026:**
- `canonical_url` pointing to Medium prevents duplicate content penalty and drives Medium followers
- `series` frontmatter links all articles — significant follower growth driver
- Popular dev.to tags: `testing`, `playwright`, `automation`, `ai`, `webdev`, `tutorial`, `devops`
- Code snippets must be runnable — no pseudocode

**Output requirements:**

Frontmatter block (at top of `DevTo` column content):
```yaml
---
title: "[article title]"
published: false
tags: [testing, playwright, ai, automation]
canonical_url: https://medium.com/@qawalah/[MediumSlug]
cover_image: /images/YYYY-MM-DD-medium.png
series: "QA Walah Weekly"
---
```

Article body: ~2000 words, Markdown, with at least one TypeScript or Python code snippet. Technical depth: explains the implementation, not just the concept.

## 15. Orchestration & Pipeline

### `runPipeline()` Flow

```typescript
async function runPipeline(): Promise<void> {
  if (isPipelineLocked()) {
    logger.warn("Pipeline already running — skipping trigger")
    return
  }

  acquireLock()

  try {
    // Check for existing today's row and handle collision
    const existingRow = await excelManager.getTodayRow()
    if (existingRow?.status === "Done") {
      logger.info("Already completed for today — skipping")
      return
    }

    const startStep = resolveStartStep(existingRow?.status)

    if (startStep <= 1) {
      emitStatus("running", "Agent 1: Selecting pillar and generating topic...")
      await agent1TopicGenerator()
    }

    if (startStep <= 2) {
      emitStatus("running", "Agent 2: Writing platform content...")
      await agent2ContentWriter()
    }

    if (startStep <= 3) {
      emitStatus("running", "Agent 3: Generating images...")
      await agent3ImageGenerator()
    }

    emitStatus("idle", "Pipeline complete — content ready")
    logger.info("Pipeline completed successfully")

  } catch (err) {
    emitStatus("error", `Pipeline failed: ${String(err)}`)
    logger.error("Pipeline failed", err)
  } finally {
    releaseLock()
  }
}
```

### `resolveStartStep()` Logic

```typescript
function resolveStartStep(status: StatusEnum | undefined): number {
  switch (status) {
    case undefined:
    case "Pending": return 1
    case "Writing": return 2
    case "Imaging": return 3
    case "Done":    return 99  // skip all
    case "Error":   return 1   // restart from beginning on error
    default:        return 1
  }
}
```

### Scheduler Setup (`instrumentation.ts`)

```typescript
// app/instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === "nodejs") {
    const { startScheduler } = await import("../lib/scheduler")
    startScheduler()
  }
}
```

`startScheduler()` reads `cronSchedule` and `timezone` from config and registers the node-cron job. When config is updated via `POST /api/config`, the old job is stopped and a new one registered immediately.

## 20. Error Handling & Recovery

| Scenario | Behavior |
|---|---|
| Deepseek API key missing | Block pipeline start; show red badge in UI; do not attempt any API call |
| Gemini API key missing | Block Agent 3 only; Agents 1 and 2 can still run |
| Deepseek rate limit (429) | Wait 10 seconds, retry once. If still 429, mark that platform as Error and continue to next |
| Deepseek timeout | Retry once after 5 seconds. If timeout again, mark as Error |
| Gemini image generation fails | Set image path to empty string in Excel; set `Status = "Error"`; preserve all content from Agent 2 |
| Gemini returns corrupt/empty image | Detected by file size check (<10KB); same handling as above |
| Excel file locked by another process | Retry write after 2 seconds, up to 3 attempts. Log warning each attempt. |
| Excel file missing on startup | `ExcelManager.ensureFileExists()` creates it with correct headers automatically |
| Pipeline triggered while already running | Return `409 Conflict` from API; log warning; no second pipeline starts |
| Today's row is `Done` | Return early with `200 OK` and message "Already completed for today" |
| Partial content (e.g. Medium failed, others done) | Preserve written columns; set `Status = "Error"`; log which platform failed; re-trigger resumes from failure |
| Config file missing or corrupt | Use hardcoded defaults; log warning; create fresh config file from defaults |
| `public/images/` directory missing | Create directory on startup and before every Agent 3 run |

## 26. Future — Agent 5 Architecture Plan

Agent 5 is planned for v2. The v1 schema and config already include all necessary placeholder columns and config blocks. No retrofitting required.

### Agent 5 — Publisher & Notifier

**What it does:**
1. Reads today's completed row from Excel
2. Checks `autoPost.platforms` config for enabled platforms
3. Posts to enabled platforms via their APIs
4. Updates `[Platform]PublishStatus` columns to "Published" or "Error"
5. Sends notification via configured channel (Telegram/email) with a summary

**Platform API availability for auto-posting:**

| Platform | Auto-Post Possible | Method | Notes |
|---|---|---|---|
| LinkedIn | Yes | LinkedIn API v2 | Requires OAuth 2.0 app |
| dev.to | Yes | dev.to API key | Simple REST, no OAuth |
| Medium | Yes | Medium Integration Token | Publishes as draft |
| Instagram | Restricted | Instagram Graph API | Requires Business account + Meta app review |
| YouTube | Restricted | YouTube Data API v3 | Video upload only — script cannot be auto-posted |

**Notification channels (v2):**
- Telegram: send message to configured `telegramChatId` via Bot API
- Email: nodemailer with SMTP config

**What creator approves before auto-post:**
- The "Ready to Publish" toggle per platform in dashboard (v2 addition)
- Agent 5 only posts platforms where toggle is ON
